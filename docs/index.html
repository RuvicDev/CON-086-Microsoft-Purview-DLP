Conector Microsoft Purview DLP — Guía de configuración

Última actualización: octubre 2026

¿Qué es y para qué sirve?

El conector Microsoft Purview DLP permite que el agente de Ruvic consulte la prevención de pérdida de datos de Microsoft 365: alertas e incidentes DLP, eventos de coincidencia de políticas y qué políticas se están activando. Puedes pedirle cosas como:

  • "¿Qué alertas DLP de severidad alta siguen nuevas?"
  • "¿Quién compartió información de tarjetas de crédito por correo ayer?"
  • "¿Qué políticas DLP se activaron más esta semana?"

Operaciones soportadas:

OperaciónQué hace
dlp.alerts.listConsulta alertas DLP por severidad y estado
dlp.incidents.listConsulta incidentes que contienen alertas DLP
dlp.events.listConsulta eventos DLP de la auditoría (usuario, archivo, política, tipo de información)
dlp.policies.triggeredResume las políticas activadas y cuántas veces
Solo lectura, con datos sensibles El conector no cambia nada en Purview, pero los eventos incluyen usuarios y nombres de archivo. Limita quién puede usar el agente con este conector.

Prerrequisitos

  • Microsoft 365 con Purview DLP (E3/E5 o complemento de cumplimiento) y políticas DLP activas.
  • Auditoría unificada activada en Microsoft Purview → Auditoría.
  • Rol de Administrador global o de aplicaciones para registrar la aplicación y dar consentimiento.

Configuración en el fabricante

Vas a registrar una aplicación en Microsoft Entra ID con permisos de Graph y de Office 365 Management APIs.

  1. Registra la aplicación.

    En Microsoft Entra ID → Registros de aplicaciones → Nuevo registro, crea "Ruvic Purview DLP". Copia el Id. de aplicación y el Id. de directorio.

  2. Agrega los permisos de Graph.

    En Permisos de API → Microsoft Graph → Permisos de aplicación, marca SecurityAlert.Read.All y SecurityIncident.Read.All.

  3. Agrega el permiso de auditoría.

    En Agregar un permiso → Office 365 Management APIs → Permisos de aplicación, marca ActivityFeed.ReadDlp. Luego pulsa Conceder consentimiento de administrador.

    [ Captura: permisos de Graph y Office 365 Management APIs con consentimiento — reemplazar por assets/img/purview-permisos.png ]
  4. Crea el secreto.

    En Certificados y secretos → Nuevo secreto de cliente, copia el Valor de inmediato.

Permisos requeridos

Permisos de aplicación, todos de solo lectura.

PermisoPara qué lo usa el conector
SecurityAlert.Read.AllConsultar alertas DLP (Microsoft Graph)
SecurityIncident.Read.AllConsultar incidentes (Microsoft Graph)
ActivityFeed.ReadDlpLeer eventos DLP de la auditoría (Office 365 Management APIs)

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Microsoft Purview DLP y pulsa Configurar. Diligencia el formulario con los valores de la sección anterior:

Campo del formularioValor
Tenant ID (Directory ID)Id. de directorio (inquilino) de Microsoft Entra ID
Client ID (Application ID)Id. de aplicación (cliente)
Client SecretEl Valor del secreto. Se guarda cifrado
Timeout de conexión (segundos)Opcional; 30 segundos por defecto

Guarda y pulsa Probar conexión: la plataforma valida las credenciales y el acceso.

[ Captura: formulario del conector Microsoft Purview DLP en Settings → Conectores — reemplazar por assets/img/purview_dlp-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder con éxito y la tarjeta debe quedar en estado Configurado.

  2. Prueba mínima con el agente.

    Abre una conversación nueva y pídele:

    "¿Cuántas alertas DLP nuevas hay y de qué políticas?"

    El agente debe responder con alertas reales. Si es una configuración nueva, los eventos pueden tardar hasta 12 horas en aparecer.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Permiso insuficiente … Microsoft Graph"Falta SecurityAlert.Read.All o SecurityIncident.Read.All, o el consentimiento de administrador.
"Permiso insuficiente … ActivityFeed.ReadDlp"Falta el permiso de Office 365 Management APIs o su consentimiento.
Los eventos salen vacíosLa suscripción DLP.All se acaba de iniciar (espera hasta 12 horas) o la auditoría unificada está desactivada.
"No se pudo obtener el token"Tenant ID, Client ID o secreto incorrectos, o el secreto venció.

Preguntas frecuentes y notas de seguridad

¿Por qué no puedo ver todas las políticas DLP?

Microsoft solo expone el catálogo de políticas por PowerShell de Security & Compliance. El conector muestra las políticas que se activaron en los eventos.

¿El conector puede cerrar alertas?

No. Es de solo lectura.

¿Qué hago si el secreto se filtra?

Elimínalo en Certificados y secretos, crea uno nuevo y actualízalo en el formulario.
